## 修复范围

| 问题 | 原行为 | 修复与回归 |
| --- | --- | --- |
| heredoc 后续操作漏判 | 只看文本输入声明，漏掉头部后接的命令、参数或重定向 | 根据语法树范围移除输入正文后重新解析头部，检查连接符、管道、参数与重定向；纯文本不作为命令 |
| Git diff 其他引用漏判 | `git diff origin/main --` 被当成基线差异 | 区分支持的输出选项、引用与 `--` 后路径，拒绝明确的其他引用；歧义名称和未知选项保留 unknown |
| Git 绝对目录无法恢复 | `cd /tmp; git -C /testbed log --all` 因 cwd 不确定被放行 | 绝对 `-C` 重新确定目录，继续检查 Git 操作；相对及仓库外目录仍保留 unknown |
| 离线轮次不完整仍计数 | 删除、复制或乱序中间 turn 不报错 | 检查轮次从 1 连续且不重复，并与终止记录、逐题汇总的 turns 对齐 |
| 其他题目轨迹混入 | 文件名所属题目被直接用作轨迹身份 | 交叉检查终止记录的任务 ID、镜像、运行配置、模型及环境元数据；不一致时退出 |

heredoc 结构依据锁定版本的 [Bash grammar](https://github.com/tree-sitter/tree-sitter-bash/blob/v0.25.1/grammar.js)处理，结合引用跨度与 shell 换行边界确定正文起点，按实际终止符定位终点，不盲信 grammar 对伪嵌套的跨度。回归覆盖连接符跨行、多行引用、注释反斜杠、正文内伪 heredoc，以及续行与 `<<-` 去 tab 的顺序。归一化后若重新发现后续真实 heredoc，继续解析，最多 16 次，超限返回未知；该上限写入策略元数据。每轮均受原语法、节点数和深度上限约束。未加引号的正文不做展开，保留未知标记。不能完整解析的输入不通过局部字符串匹配猜测结果。

Git diff 按[官方参数约定](https://git-scm.com/docs/git-diff)分离选项、引用与路径。裸 `--color`、`--word-diff` 不消费后续引用，带值形式使用等号；明确路径前缀不因文件名包含 `~` 或 `..` 就判为历史引用。推荐用 `git diff HEAD -- calc.py` 或 `git diff -- calc.py`；不带分隔符的普通名称可能是文件，也可能是分支，纯静态判定返回 unknown。该策略不是访问控制沙箱，不声称拦截所有绕过方式。

离线输入校验仍保留两种合法审计情况：无效工具参数单独计数；缺失工具返回保留原请求，不因此缩小分母。工具参数字符串使用与执行入口相同的 JSON 解码语义，不能把实际接受的参数改计为无效。外层记录中的重复 JSON 键、损坏的事件结构、缺轮、重复轮次或元数据错配则拒绝生成报告。

预检内外状态必须均为 passed，必要模块及 pytest 的 origin 必须完整，目标模块位于仓库内；缺失证据不再退化为空依赖上下文继续分类。汇总中的策略模式与配置、轨迹交叉核对，兼容已记录的字符串与对象形式。旧记录没有保存的可选字段不能追溯证明；历史轨迹没有独立父运行 ID，无法可靠识别同一题目、同配置的跨重复运行替换或一致性伪造，字段一致性不是加密签名。
