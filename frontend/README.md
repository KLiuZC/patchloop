# patchloop 工作台

React + JavaScript + Vite 前端，连接已有 FastAPI 与独立 worker。组件使用 `.jsx`，请求和解析逻辑使用 `.js`。

## 启动

需要 Node.js 20.19+ 或 22.12+；本地开发已在 Node.js 25.8.0 验证。

在项目根目录启动任务 API：

```bash
uv run agent serve
```

另开终端，在项目根目录启动前端：

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

打开 `http://127.0.0.1:5173`。前端通过 `/api` 代理连接 `http://127.0.0.1:8000`，浏览器无需额外的跨域配置。只查看历史记录不会调用模型。

需要处理新任务时，再开一个终端运行：

```bash
uv run agent worker
```

worker 会串行处理带执行配置的排队任务，实际执行将调用所选模型。也可以先通过网页创建一题，再使用 `uv run agent worker --task-id "<task_id>"` 只执行该任务。没有启动 worker 时，新任务保持排队；旧的无执行配置记录仅展示，不会执行。

API 和 worker 使用同一个数据库；自定义数据库时，两条命令都传同一个 `--db`。前端无需知道数据库路径。

## 页面

| 地址 | 功能 |
| --- | --- |
| `/tasks` | 历史任务、执行状态筛选、自动刷新和游标分页 |
| `/tasks/new` | 填写目标与验证命令，选择模型、镜像和预算 |
| `/tasks/:taskId` | 执行/验证状态、代码 diff、逐轮日志、验证输出、人工审查和产物下载 |

执行完成与验证通过分别展示。接口请求失败时展示错误并允许重试；提交不自动重发，提交结果不明确时先检查历史列表。页面刷新或关闭不会取消后台任务。

表单会保留仓库路径和验证命令中的有效空格；模型和镜像名称遵循后端的格式限制。示例按钮只填充表单，点击“提交任务”才发送请求。

日志和补丁以纯文本展示，模型推理字段不直接展示在执行轨迹中。运行结束时重新读取最终日志；损坏或截断记录保留告警与原始日志入口。费用为后端记录的估算值，未知时显示 `—`。

“修复过程”中的验证结果按“修复前 / 修复后”上下排列，左侧以括号形连接线标明两者关系，连接线随日志展开和收起自动延伸。测试输出保留展开/收起，展开后长行自动换行；较长日志可在放大的输出区域内滚动，也支持键盘聚焦后滚动。

详情新增“人工审查”页签。概览中的审查状态读取独立审查接口，不再使用原始 `result.review_status`。当前状态定时更新，历史按最新在前展示，审查意见作为纯文本显示。接受/拒绝只保存决定，不应用补丁或创建 Git 分支。

接受后，“本地交付”卡片展示批准版本、基线、目标分支、工作区、路径规则与实际修改文件。点击“生成修改分支”才提交交付；提交前重新核对计划与审批，不自动采用变化后的目标。完成后显示分支、提交 SHA 和可复制的工作区路径，保留原工作区的改动。HEAD 与验证基线不一致时会阻止交付，旧任务不能直接套用到新版本。

同一审查的重复请求返回同一份交付。网络异常时保留原请求供核对或重试；进行中的记录提供“恢复交付”，只使用该记录绑定的参数，不自动 POST。恢复允许核对已发布但尚未记完的历史尝试，新交付仍必须满足最新有效批准。迟到的 preparing 响应不能覆盖已知终态；已完成输出变化时显示提示，不覆盖现有文件。

新建任务的高级设置增加允许与禁止修改的路径，按仓库根目录相对模式逐行填写。默认保护常见测试路径，规则会保存到任务，并在独立验证和交付中检查。修改这些设置只影响新任务。

进入审查页后，核对任务、摘要、补丁及验证报告的原始 SHA-256，前后两次读取审查状态必须一致。展示的要求、代码和测试输出来自这组资料；写意见期间保持资料不变。提交前再次检查当前版本及证据；发生变化时保留意见，要求显式重新加载并核对，不自动改用新证据提交。状态读取失败、资料不一致或后端不允许操作时禁用相应按钮。

普通意见草稿按任务保留在当前页面会话中，切换页签或任务后可恢复。提交不自动重试；结果不明确时保留原请求编号、意见和证据，提供“核对提交结果”和“重试原提交”。浏览器会话存储可用时，刷新页面后仍能恢复未确认请求；存储不可用时保留内存副本。恢复不会自动发送请求。已有较新的审查版本不会被迟到的旧查询或旧提交响应覆盖。

一旦网页已观察到审查过期，同一版本的迟到响应不会把状态恢复为已接受；需要点击“重新加载审查资料”重新核对。离开页面时尚未完成的提交前检查不会继续发起新提交；已发送的请求仍可按原编号恢复和核对。

首版采用浅色布局，支持桌面、窄屏、键盘焦点及详情标签页方向键操作。系统启用减少动态效果、减少透明度或增强对比度时，页面相应调整。

模型提供方、镜像架构和任务状态筛选共用 Radix Select。箭头距右侧内边框 14px，选项菜单与控件等宽，默认向下展开并留出 8px 间距；空间不足时向上展开或限制菜单高度。支持方向键选择、Enter 确认、Escape 关闭与焦点返回。“自动选择”和“所有状态”的空值由组件内部适配，提交给 API 的参数保持原有含义。

## 配置

后端端口不为 8000 时，可以在前端目录复制配置示例：

```bash
cp frontend/.env.example frontend/.env.local
```

将 `PATCHLOOP_API_TARGET` 修改为任务 API 地址，重启前端即可。该变量只用于开发/预览服务器代理。模型密钥仍放在后端配置中，前端表单和环境变量均不需要模型密钥。

默认开发端口 5173、预览端口 4173，端口被占用时会直接报错。可以用 `npm --prefix frontend run dev -- --port 5174` 指定其他端口。

## 检查与构建

```bash
npm --prefix frontend test
npm --prefix frontend run lint
npm --prefix frontend run build
npm --prefix frontend run preview
```

测试使用模拟请求，覆盖列表与分页、状态分离、表单校验及重复提交、终态日志更新、请求失败、残缺轨迹和 diff 解析，以及审查证据核对、版本冲突、同请求重试和任务切换隔离。初版修复联调使用隔离数据库与脚本化模型，复用真实 Docker 修复和独立验证流程；审查页另用数据库临时副本验证接受、拒绝、历史及刷新恢复，不调用模型或向原任务库写入审查记录。

`preview` 用于本地检查 `dist/` 构建结果，并保留 `/api` 代理。部署静态文件时需要配置 SPA 路由回退和 `/api` 反向代理，不能把预览服务器当作多人生产部署方案。

## 代码结构

```text
src/
  main.jsx           React、路由、查询缓存与动态效果设置
  App.jsx            页面路由
  pages/             列表、新建任务与详情
  components/        布局、状态、统一选择框、diff、日志与通用反馈
  lib/api.js         请求封装、响应校验与错误处理
  lib/query-client.js 查询缓存、重试和本地网络模式
  lib/artifacts.js   JSONL 轨迹和统一 diff 解析
  lib/task.js        状态文案、时间格式与表单数据
  styles.css         工作台样式与响应式/可访问性适配
  test/              页面测试与模拟数据
```
