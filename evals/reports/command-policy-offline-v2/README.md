# 命令策略 v2：有限 Git 查询调整

[v1 离线报告](../command-policy-offline-v1/README.md) · [策略说明](../../../docs/command-policy.md) · [发展路线](../../../ROADMAP.md)

日期：2026-10-19。状态：规则调整、执行层回归及同输入离线对照已完成；没有调用真实模型、重放旧命令或改变默认关闭设置。v1 报告保持原样。

## 调整范围

v1 将 `git log --oneline -3/-5/-8` 等有限查询也视为历史搜索，导致与其连写的正常源码读取被整条拒绝。v2 增加有条件的元数据查询例外，不放开所有 Git 操作：

- 没有初始历史隔离证明时，仍只允许 `HEAD` 的单条元数据查询。
- 有证明时，允许最多 10 条元数据，数量必须显式指定且只出现一次；支持 `-N`、`-n N`、`-nN`、`--max-count=N` 和 `--max-count N`。
- 提交选择仅允许省略或显式 `HEAD`，不允许其他分支、提交 SHA、`HEAD~1` 或范围，也不增加按文件路径筛选的例外。
- 支持 `--oneline`、`--no-decorate` 以及使用等号的 `--format=...`／`--pretty=...`。格式字符串里的 `-3` 是文本，不当作数量选项；重复、零值、负数、超限或歧义形式不放行。
- `--all`、`-S/-G`、patch/stat/raw 等代码或差异输出、skip/grep 等历史筛选、reflog、fsck 和对象枚举继续拒绝。复合命令含其他禁止操作时仍整条拒绝。

Git 的参数形式按[官方 log 文档](https://git-scm.com/docs/git-log)核对；10 条是本策略选择的固定上限，不是 Git 本身的限制。未知包装、自定义 Git 配置和动态 shell 仍按原规则处理。

`isolated_history` 默认 `False`。SWE-bench 上下文构建器从通过预检的报告中核对任务 ID、完整 base SHA、HEAD、仅一个 commit 对象、没有远端/reflog/alternates，以及无已跟踪修改后，才设置为 `True`。缺失或不一致的历史证据不启用新例外。

该标记记录的是模型开始前的快照，不是每条命令执行前重新证明 Git 状态，也不保证未知程序随后无法修改仓库。直接调用纯判定器时，上下文仍由调用方负责；它不是模型可自行设置的工具参数。

版本分别更新为 `command-policy-v2`、`swebench-command-context-v2` 和开发样例版本 2，配置记录新增 `git_log_metadata_commits=10`。环境隔离策略仍为 `swebench-isolation-v2`，没有改动缓存遮蔽或 Git 隔离实现。

## 相同输入的结果

重新分类的是原十遍三题轨迹的同 985 条 bash 请求，仍有 6 条非 bash 请求。输入文件哈希、题单、命令文本、参数哈希、工具返回哈希、轨迹行号和调用 ID 均与 v1 相同；没有因结果改变而删选请求。

| 分类 | v1 | v2 | 变化 |
| --- | ---: | ---: | ---: |
| allow | 689 | 711 | +22 |
| block（拟拦截） | 95 | 66 | -29 |
| unknown | 201 | 208 | +7 |
| 合计 | 985 | 985 | 0 |

改变的 29 条请求恰好对应 v1 复核中的 `scope_tradeoff` 集合；其余 956 条的分类与规则保持一致。原来归为 `intended_block` 的 66 条全部仍是 block。逐条变更见 [comparison.json](comparison.json)。

| 原实验组 | bash 请求 | allow | block | unknown |
| --- | ---: | ---: | ---: | ---: |
| DeepSeek 基线三遍 | 301 | 215 | 23 | 63 |
| DeepSeek 提醒三遍 | 280 | 209 | 9 | 62 |
| DeepSeek 提醒 + finish 三遍 | 301 | 211 | 29 | 61 |
| GLM 基线一遍 | 103 | 76 | 5 | 22 |

7 条新 unknown 中，6 条包含 `python -c`，1 条包含尚未支持的 `git describe --tags`。移除有限 log 的禁止判定后，剩余的不透明部分重新显现；不把这些请求硬标为 allow。当前 enforce 对 unknown 仍原样执行并记录。

因此明确分类范围从 79.6% 变为 78.9%，未知率从 20.4% 变为 21.1%；拟拦截占比从 9.6% 变为 6.7%。覆盖率稍降不是新增解析故障，也不能反过来把比例提升当作目标。禁止规则命中中，history_search 从 47 次降到 18 次，其他禁止规则的命中次数不变。

## 结果边界

这是针对已知开发样本的规则修订，不是独立留出检验。29 条风险命令已用于确定新规则；只能说明这些已知干扰在当前规则下不再被拒绝，不能声称总体误拦截率下降了某个百分比或已经为模型节省轮数。

源轨迹仍来自隔离策略 v1。新上下文使用旧预检快照中的 Git 事实重建证明，30 次尝试均满足初始隔离条件；没有把源模型运行改称为 v2 环境的新评测。模型收到不同反馈后会改变命令序列，本报告不推算新的解决率和费用。

v1 的 95 条拟拦截已有逐条复核。本轮逐条核对 29 条变更，同时确认原 66 条限制未被放行；没有建立全体正常／禁止命令的独立真值，仍不能宣称“零误拦截”或计算总体准确率、漏拦率。
