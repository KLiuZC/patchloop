## 求解环境策略 v1

`agent eval` 和 `agent repair-swebench` 在首次模型请求前执行相同预检：

1. 将镜像标签解析为实际 image ID，本次求解按该 ID 启动。
2. 以只读空 tmpfs 遮蔽 conda 缓存、root 缓存及额外用户目录 `/home`；关闭网络、移除 capabilities、禁止提权。保留 `/root/.bashrc` 中的 conda 环境配置。
3. 从题目指定 base commit 建立单提交浅对象库，替换求解副本的 `.git`。保留原始 commit ID 与文件树，移除其他提交、远端和 reflog。该策略有意减少历史信息，后续对照组必须采用相同策略。
4. 检查常见安装与缓存目录中的被测包同名副本、同名发行包，以及常见评测材料；检查扫描错误、Git 状态、模块导入位置和 pytest 导入。
5. 将报告保存在容器外。检查未通过时不调用模型；预检失败不交给官方判卷当作模型答错，含此类失败的批次不输出完整解决率。

检查策略、扫描目录、helper 哈希和 image ID 进入报告；策略也进入 `run_config.json`。既有运行不能混入新配置，需使用新 run-id。通用 `agent run` 和网页本地仓库任务未自动纳入本次 SWE-bench 策略。

扫描是按明确目录和文件特征进行的，不覆盖任意改名源码、任意压缩包内容或模型训练数据。当前仅完成 xarray-4687 的真实镜像验收；其他仓库的配置仍需逐题核对。

## 不调用模型的单题预检

提前准备目标镜像，在新的产物目录执行：

```bash
uv run agent preflight-swebench \
  --instance pydata__xarray-4687 \
  --verify 'python -m pytest -q xarray/tests/test_computation.py -k test_where' \
  --artifacts /tmp/patchloop-preflight-4687-new
```

此命令不初始化模型客户端、不读取提供商凭据，也不自动下载或构建镜像。题目元数据使用已有数据集加载入口；可用 `HF_HUB_OFFLINE=1` 读取本地数据集缓存。`--verify` 应是已存在的可见检查，预检要求它正常退出（0）；不要使用 gold 补丁或隐藏测试作为该命令的输入。

产物：`preflight.json` 包含原环境检查、隔离后检查及可见测试输出；`environment.json` 是实际求解前使用的隔离检查。扫描或导入失败时报告保留，退出码为 2。
